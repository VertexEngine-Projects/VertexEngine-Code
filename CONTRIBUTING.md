# Contributing to VertexEngine

Thank you for contributing to VertexEngine's open-source environment! But first, before contributing, READ THIS FILE BEFORE CONTRIBUTING AND REPORTING BUGS. YOUR REPORT MUST BE CLEAR AND WILL BE SKIPPED IF IT DOES NOT FOLLOW THIS FILE.

---

## How Can I Contribute?

### Reporting Bugs
Before creating a Bug Report, check if the bug has been reported by someone else, if it hasn't, first Open an Issue and add:
* A clear, descriptive title.
* Steps to reproduce the problem.
* The specific version of Python and VertexEngine you are using.
* Any relevant error messages or console logs.

### Suggesting Enhancements
Do you have a great idea to improve VertexEngine? Show me:
* The feature you want to see.
* Why it would be useful to other developers.
* Examples of how the new code or syntax might look.
* If you send enough good improvements, you can be a maintainer of the VertexEngine MAIN PYPI package!

### Submitting Code Changes (Pull Requests)
Do you have a rewritten version of VertexEngine? Here is how to submit your changes:
1. **Fork** the repository to your own GitHub account.
2. **Clone** your fork locally and create an isolated feature branch (`git checkout -b feature/amazing-feature`).
3. Write your clean, well-commented Python code.
4. Keep your changes focused. Try not to mix multiple unrelated fixes into a single commit.
5. **Push** your branch to GitHub and open a **Pull Request (PR)** against my `main` branch.

---

## Code of Conduct

* **Be Respectful:** Treat all contributors, users, and maintainers with kindness and respect.
* **Stay Collaborative:** Be open to feedback and suggestions during code reviews.
* **Keep it Clean:** Ensure your contributions do not contain malicious code, telemetry, or hidden trackers.
